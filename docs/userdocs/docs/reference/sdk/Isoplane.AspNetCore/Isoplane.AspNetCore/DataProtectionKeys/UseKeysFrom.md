# DataProtectionKeys.UseKeysFrom method

Keeps the keys in a store the application reaches asynchronously, such as its database. The keys are loaded during initialization, and a new one is created and stored if none is usable. Instances use the keys captured in their template.

```csharp
public static IDataProtectionBuilder UseKeysFrom(this IDataProtectionBuilder builder,
    Func<IServiceProvider, CancellationToken, Task<IReadOnlyCollection<XElement>>> load,
    Func<IServiceProvider, XElement, string, CancellationToken, Task> store)
```

| parameter | description |
| --- | --- |
| builder | What `AddDataProtection` returned. |
| load | Returns every key element the store holds. It is given a service scope of its own. |
| store | Adds one key element, with the name Data Protection gives it, to the store. It shares *load*'s scope. |

## Return Value

*builder*.

## Remarks

Loading happens after every `Initialization.Initializing` callback has finished, so a callback that creates the store's tables runs first. A callback that itself protects or unprotects data, for instance by warming up a page with a form, awaits [`LoadDataProtectionKeysAsync`](./LoadDataProtectionKeysAsync.md) before it does. Each prepared template keeps its captured keys, even after they expire. Preparing a new template may load newer keys; reusing a template reloads none.
