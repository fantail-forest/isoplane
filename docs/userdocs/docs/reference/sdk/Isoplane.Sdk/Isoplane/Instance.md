## Remarks

Isoplane initializes the application ahead of requests and saves its memory as a template. It then scales copies of the application with traffic, up to the application’s instance limit. Each copy is an instance and starts from the template. Whatever existed when the template was saved is therefore identical in every instance, including a random value drawn at start-up. Subscribe to [`Starting`](./Instance/Starting.md) to replace such state when an instance starts.

Isoplane already reseeds, before the event is raised, every `Random` created without a seed, `Random.Shared`, the generator behind `Activity` trace and span identifiers, and the one behind SQLite's `random()` and `randomblob()`. Cryptographic randomness needs nothing: each call draws fresh bytes. Three things are left to you: a `Random` constructed with a seed, even when that seed was itself random; a generator that is not a `System.Random`, such as one a library implements; and a value already drawn, such as an identifier stored in a static field.

An application written without ASP.NET has no start-up code to subscribe from, and marks one method with [`InstanceStartAttribute`](./InstanceStartAttribute.md) instead. For state that every instance can share, use [`Template`](./Template.md). [The application lifecycle](../../../../concepts/application-lifecycle.md) explains templates and instances in full.

## Examples

In `Program.cs`, before `await app.RunAsync()`:

```csharp
var instance = Guid.Empty;

Instance.Starting += () =>
{
    instance = Guid.NewGuid();
    return Task.CompletedTask;
};
```
