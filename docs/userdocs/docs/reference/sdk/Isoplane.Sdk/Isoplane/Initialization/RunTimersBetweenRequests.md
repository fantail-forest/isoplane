# Initialization.RunTimersBetweenRequests method

Wakes the application's idle instances to run timers that have come due, at most once per *minimumInterval*.

```csharp
public static void RunTimersBetweenRequests(TimeSpan minimumInterval)
```

| parameter | description |
| --- | --- |
| minimumInterval | The least time between the end of one request or wake and the next wake: at least 100 milliseconds. |

## Exceptions

| exception | condition |
| --- | --- |
| ArgumentOutOfRangeException | *minimumInterval* is less than 100 milliseconds. |
| InvalidOperationException | Initialization has finished. |

## Remarks

Without this call, a timer that comes due while an instance has no request to handle runs at the start of the instance's next request. With it, an idle instance is also woken to run its due timers, no sooner than *minimumInterval* after its last request or wake ended; a timer due earlier waits until then. Timers that come due during a request run on time either way.

Wakes are best effort: an instance that has had no request for five minutes is stopped instead of woken, and an instance Isoplane has set aside to save memory runs its timers only when its next request arrives. Use a timer between requests for upkeep such as flushing telemetry, not for work that has to happen on schedule.

In local development and tests, each periodic timer is reported in the log with how often it fires and how many wakes the instance's timers can cause.

The setting applies to every instance, so call this during initialization: from an [`Initializing`](./Initializing.md) callback, or from the method marked with [`InitializerAttribute`](../InitializerAttribute.md). A later call replaces the interval an earlier one set.

## Examples

```csharp
Initialization.RunTimersBetweenRequests(minimumInterval: TimeSpan.FromMinutes(1));
```
