# IsoplaneOtlpExporterExtensions.AddIsoplaneOtlpExporter method

Exports finished spans with OpenTelemetry's OTLP exporter, sending each request's spans after its response instead of blocking while they are sent, which the sandbox cannot do. Use it in place of `AddOtlpExporter`.

```csharp
public static TracerProviderBuilder AddIsoplaneOtlpExporter(this TracerProviderBuilder builder,
    Action<OtlpExporterOptions>? configure = null)
```

| parameter | description |
| --- | --- |
| builder | The tracing builder, as `WithTracing` passes it. |
| configure | Sets OtlpExporterOptions, after the `OTEL_EXPORTER_OTLP_*` settings in the application's configuration. Leave it out to use those settings alone. |

## Return Value

*builder*.

## Exceptions

| exception | condition |
| --- | --- |
| InvalidOperationException | It is called a second time for the same application. |

## Remarks

Spans are held in the instance's memory until a span with no parent in the application ends, which for a web request is the request's own span. They are then encoded and sent while the client already has the response. Work remaining after response completion uses the instance's background allowance. [`FlushAsync`](../TraceExport/FlushAsync.md) sends them sooner.

Spans still held when the instance is stopped are lost, and an export the endpoint refuses is logged and not retried. ExportProcessorType is ignored; BatchExportProcessorOptions sets how many spans are held and how many go in one export.

## Examples

```csharp
builder.Services.AddOpenTelemetry()
    .WithTracing(tracing => tracing
        .AddAspNetCoreInstrumentation()
        .AddIsoplaneOtlpExporter());
```
