# SessionLoading.UseLoadedSession method

Adds ASP.NET Core's session middleware, as `UseSession` does, and loads each request's session from the cache asynchronously before the rest of the pipeline runs, so that the session and TempData kept in it work over a distributed cache. Call it in place of `app.UseSession()`.

```csharp
public static IApplicationBuilder UseLoadedSession(this IApplicationBuilder app)
```

| parameter | description |
| --- | --- |
| app | The application's pipeline. |

## Return Value

*app*.

## Remarks

Register the session and its cache as usual, with `AddSession` and an `IDistributedCache`; the options given to `AddSession` apply. For Redis, reference the stable StackExchange.Redis 3.x client directly; see [Redis compatibility](../../../../../concepts/library-compatibility.md#redis).

Every request that passes through the middleware reads the cache once, whether or not it uses the session. Place it after middleware that answers requests without a session, such as `UseStaticFiles`, so those requests make no read. A failed read fails the request with the cache's exception.

## Examples

```csharp
builder.Services.AddStackExchangeRedisCache(options =>
    options.Configuration = builder.Configuration.GetConnectionString("Redis"));
builder.Services.AddSession();
var app = builder.Build();

app.UseStaticFiles();
app.UseLoadedSession();
```
